# 本机定位精度数据增强

模型输入为中文 `intent` 和位置证据 `slots`。三分类标签为精确、区域级模糊、城市级模糊。原话与理由用于复核。所有新增原话均为人工设计的合成场景，由模型辅助编写。候选测试集尚未经过独立人工标注。

| 文件 | 内容 |
| --- | --- |
| `cases.tsv` | 139 条可编辑的合成场景及逐条标注依据 |
| `synthetic.jsonl` | 同一批场景的 JSONL 导出，按 `split` 筛选 |
| `build.py` | 归并现有训练集、加入新语义组合、生成隔离的三分类评估集 |
| `evaluate.py` | 用 CPU 训练加权逻辑回归，比较增强前后以及是否使用槽位 |
| `verification.json` | 实际运行的统计及评估结果 |

## 生成与训练

使用 v11 仓库、Python 3.10+ 和上一步合并输出中的 `model` 目录。在本仓库根目录运行以下命令，将路径换成服务器上的实际路径。

```bash
python3 data-balance-v12/build.py \
  --repo . \
  --base-model-dir /path/to/data-location-coverage/model \
  --out ./data-location-balance-v12

python3 -m pip install scikit-learn
python3 data-balance-v12/evaluate.py --data-dir ./data-location-balance-v12
```

生成目录中的 `model/train.jsonl` 为增强训练集，`model/train_base_dedup.jsonl` 为相同拆分下的去重基线。使用新 `model/dev.jsonl` 和 `model/test.jsonl` 比较模型。 `audit/` 保留原始槽位、原话、依据、规则复算结果及新增样本的纳入记录。所有源数据继续可从原输入目录取得。

要训练其他模型，可直接读取 `model/train.jsonl`。归一化后还存在轻度类别不平衡，可用 `summary.json` 里的逆频率类别权重。如训练 CatBoost，可将每个槽位拓展为类别特征，将缺失填为统一值，保持 `intent` 为一个类别特征。线上输入应与训练使用相同的 `canonical` 归一化，原始槽位也应传给策略校验。首轮优先比较相同划分下的现有规则和小模型。

## 如何归并

- 保留当前设备、已知地点、保存地点等位置来源，以及来源在起点、终点、上车点或一般位置中的角色。保留搜索范围、请求粒度、操作、是否记录轨迹、触发条件和半径所在区间。
- 地名、附带地点和搜索目标名保留在原始样本，归一化训练输入用位置来源表达位置参照。同类操作只换目标名称，仍算同一个语义组合。训练、开发、测试集合按归一化组合互斥，新增样本的场景族也保持互斥。
- 补样本前先人工设计约束差异，再用 v11 规则复算训练候选标签。训练候选中已有的语义组合跳过。旧拆分用作历史对照，二者的语义重合数见 `summary.json`。
- 三分类只包含三档位置精度。「不涉及」对照和存在口径争议的样本保存在 `audit/control.jsonl` 和 `audit/review.jsonl`。后续可通过独立的位置调用保护策略评估对照。规则口径冲突需业务复核。

## 验证结果

以 10,219 条的合并版为输入。原训练集有 282 种不同的原始输入，按上述标准归为 71 种语义组合，其中 2 种留给新的候选评估集。65 条合成训练候选中加入 57 种，已有 8 种。归并后的训练集共 126 条，每个输入组合一条。

| 精度标签 | 去重后同划分基线 | 实际新增 | 增强后 |
| --- | ---: | ---: | ---: |
| 精确 | 23 | 26 | 49 |
| 区域级模糊 | 16 | 17 | 33 |
| 城市级模糊 | 30 | 14 | 44 |

下单外卖已补充明确使用本机当前位置作为配送地址的输入。默认位置与明确使用本机是两种证据状态，均标精确。固定地址与保存地址为「不涉及」对照。仅查外卖商家时以查询范围决定三档精度。

加权逻辑回归在 26 条隔离的合成测试样本上，使用去重基线时 Macro-F1 为 0.6845，使用增强数据时为 0.9602。增强后，17 条模糊样本中仍有 1 条被误放为精确。样本为「查从常州到我所在城市的长途客车」，本机只用于确定目的城市。训练和评估数据来自相近的规则体系，这些数字用于验证本轮增强流程。现网质量需要另用独立人工审核的数据评估。

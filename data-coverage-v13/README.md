# v13 本机定位精度数据扩充

以 v12 全量训练文件的 166 条为基础，按位置参照及角色、查询约束、业务动作和触发条件构造合成组合。涵盖原 22 个领域及本地新闻。领域分布和逐类数量见 `summary.json`。

| 指标 | 数量 |
| --- | ---: |
| 保留的 v12 样本 | 166 |
| 新进入训练的组合 | 235 |
| 三分类训练组合 | 401 |
| 精确 / 区域级模糊 / 城市级模糊 | 173 / 100 / 128 |
| 训练覆盖意图 / 领域 | 43 / 23 |
| 合成场景覆盖意图 / 领域，含对照与复核 | 57 / 23 |
| 不涉及本机定位的对照 | 253 |

689 种合成场景中有 127 种已存在于 v12。训练集中去掉围栏来源和不直接改变精度的操作字段后，有 256 种核心组合，v12 按同口径有 166 种。这里的核心组合仍保留位置角色、搜索条件、触发动作和与定位有关的操作类型。这是归并口径下的覆盖度，业务语义仍可能近似。新增训练标签使用预写的场景预期精度，并在纳入前用仓库的 v11 标注规则复算。数据由场景矩阵合成，标签未经独立人工抽样评审，适合试验。现有 166 条也已经参与训练。

## 槽位

模型文件每行包含 `intent`、`slots` 和 `label`。继续使用 v12 的位置来源与搜索约束槽位，例如 `src`、`from_src`、`scope` 和 `radius_band`。在适用的意图中细化 `op`，例如 `browse_merchants`、`request_pickup` 和 `book_ticket`。采集不到操作字段时可省略。地理围栏的 `fence_src` 描述围栏设在哪个已知位置，`trigger` 表示检测本机进入或离开。保留这两项可表达围栏的业务语义，同时同类围栏位置来源不改变定位精度。真实交互的槽位提取器需要识别这些字段和对应取值，才能覆盖新场景。

## 在仓库中复现

在 `data-coverage-v13` 分支的仓库根目录执行，按服务器目录替换 `--base`。

```bash
python3 data-coverage-v13/expand.py \
  --base ./location-v12-full/train.jsonl \
  --out ./location-v13-expanded
```

| 输出文件 | 用途 |
| --- | --- |
| `train.jsonl` | 401 条全量三分类训练数据 |
| `added_train.jsonl` | 235 条新增三分类训练数据 |
| `synthetic.jsonl` | 689 条合成场景，含原始槽位、标签依据与规则复算结果 |
| `not_applicable.jsonl` | 253 条不涉及本机实时定位的对照 |
| `review.jsonl` | 74 条待复核或超出范围场景，包含乘车码、运动历史按当前城市筛选等口径问题 |
| `summary.json` | 标签、领域、核心组合数和训练文件校验值 |
